# 저항실패 점수 전략 — 실행 패키지

12부에서 명세한 가설 H1의 **돌아가는 구현**이다.

> **H1**: 자산이 최근 고점 돌파에 반복 실패할수록, 이후 4주 횡단면 초과수익이 낮다.

원래 직관(삼산 = 고점 돌파 반복 실패 후 하락)은 그대로다.
바뀐 것은 **재는 방법**(이산 패턴 → 연속 점수), **담는 그릇**(단일 종목 → 횡단면 롱숏),
**크기 규칙**(고정 배율 → 변동성 타게팅)뿐이다.

---

## 먼저: 얼마를 기대할 수 있는가

```bash
python3 run.py expect
```

`IR = IC × √유효BR`, `순수익 = IR × 목표변동성 − 비용`.
자산 50개·주간 리밸런싱·분산팽창 2.1배·목표변동성 20%·편측 15bp·숏 대차 200bp 기준:

| IC | 총 IR | 총수익 | 비용 | **순수익** | 손실년 확률 | t=2까지 |
|---:|---:|---:|---:|---:|---:|---:|
| **0.00** | 0.00 | 0.0% | 6.5% | **-6.5%** | 63% | — |
| 0.01 | 0.35 | 7.0% | 6.5% | **+0.6%** | 49% | 4,800년 |
| **0.02** | 0.70 | 14.1% | 6.5% | **+7.6%** | 35% | 27.6년 |
| **0.03** | 1.06 | 21.1% | 6.5% | **+14.7%** | 23% | 7.5년 |
| 0.05 | 1.76 | 35.2% | 6.5% | +28.7% | 8% | 1.9년 |

**이 표가 이 전략에 대해 알아야 할 거의 전부다.**

- **IC=0이 기본값이다.** 그 경우 순수익은 비용만큼 **음수**다. 대부분의 차트 가설이 여기 있다.
- **IC 0.02~0.03이 현실적인 성공 구간**이고, 그때 순수익 연 8~15%다. 그 위는 기대하지 않는 편이 낫다.
- **비용이 IC 0.02가 만드는 총수익의 절반을 먹는다.** 신호를 다듬는 것만큼 회전율 관리가 중요하다.
- **엣지가 진짜여도 3년 중 1년은 마이너스다.** 이걸 모르고 시작하면 첫 손실년에 그만둔다.
- **레버리지 금지 상한(gross ≤ 1.0) 때문에 실현 변동성이 목표에 미달할 수 있다.**
  실현이 목표의 절반이면 **기대수익도 절반**이다. 리포트가 이를 명시한다.

## 설치와 실행

```bash
pip install -r requirements.txt

python3 run.py expect      # 기대수익 산술 — 백테스트 전에 먼저 볼 것
python3 run.py selftest    # 파이프라인 자기검증 (귀무 vs 엣지 합성 데이터)
python3 run.py backtest --csv prices.csv --oos 2023-01-01
```

### 자기검증이 통과해야 하는 기준

```
귀무 데이터(진짜 엣지 0)  → IC +0.0004 (t=+0.04), 5개 조건 전부 미달 → 기각
엣지 데이터(IC 0.06)      → IC -0.0750 (t=-8.60), 연 +6.2%, 샤프 0.69 → 검출
```

**귀무 데이터에서 '운용 후보'가 나온다면 코드나 진단에 결함이 있는 것이다.**
실데이터를 붙이기 전에 이 검사부터 통과시킨다.

## 데이터 요구사항

`prices.csv` — `date,symbol,close` (일봉 또는 주봉; 주봉 W-FRI로 리샘플된다)

**반드시 상장폐지·상장폐지된 코인을 포함한 데이터를 쓸 것.**
살아남은 종목만으로 만든 데이터는 **어떤 결과도 무효화한다** — 이 전략은 약세 자산을 숏하므로
생존편향은 성과를 체계적으로 부풀린다. 3부 검증 E와 8부 검증 P가 그 크기를 보여준다.

## 운영 절차 (12.6)

### 1단계 — 선등록
`config.py`를 확정하고 **git에 커밋**한다. 커밋 시각이 등록 시각을 증명한다.

```bash
python3 -c "from config import DEFAULT; print(DEFAULT.describe())"
git add config.py && git commit -m "pre-register H1 <지문>"
```

**파라미터를 바꾸고 싶어지는 건 정상이다.** 바꾼 버전을 새로 커밋하고
`n_hypotheses`를 올리면 된다 — `diagnostics`가 허들을 자동으로 높인다.
**반칙은 바꾸는 것이 아니라 바꾼 사실을 세지 않는 것이다.**

### 2단계 — 표본외
`--oos` 로 등록 이후 구간만 평가한다. 과거 데이터를 쓸 거면 홀드아웃을 먼저 잘라두고 손대지 않는다.
검증 GG 기준 **약 5년**이 필요하다.

### 3단계 — 소액 실전
비용·슬리피지·실행 갭은 시뮬레이션으로 대체 불가능하다.
자본의 일부만 넣고, 실전 성과가 백테스트의 절반 미만이면 비용 가정이 틀린 것이다.

## 중단 규칙 (12.7 — 코드가 자동 판정한다)

| 조건 | 기준 | config 키 |
|---|---|---|
| IC가 0과 유의하게 다른가 | \|t\| ≥ 2.0 | `kill_ic_t` |
| 비용차감 후 수익 t값 | ≥ 1.0 | `kill_net_t` |
| 분위 단조성 | Q1→Q5 단조 | — |
| 최대낙폭 | ≤ 25% | `kill_max_dd` |
| 탐색량 보정 허들 | 샤프 ≥ √(2 ln N)/√T | `n_hypotheses` |

**분위 단조성이 가장 엄격한 검사다.** 진짜 신호는 분위 간 단조 기울기를 보인다.
극단 분위 차이만 크고 중간이 뒤죽박죽이면 신호가 아니라 소수 이상치다.

## 이 패키지가 보장하는 것과 보장하지 않는 것

**보장한다**
- 미래참조 없음 (비중·변동성 스케일 모두 1기 시차, 실패 판정은 확정 후 시차 적용)
- 비용이 회전율에 비례해 실제로 차감됨
- 귀무 데이터에서 '엣지 없음'을 올바르게 판정함 (`selftest`로 확인 가능)
- 탐색량 N에 따라 요구 허들이 자동으로 올라감
- 레버리지 불가 (`max_gross=1.0`) — 파산 경로 차단

**보장하지 않는다**
- **이 신호에 엣지가 있다는 것.** 실제 IC는 0일 수 있고, 그러면 위 표대로 비용만큼 잃는다.
  이 패키지의 목적은 **그 사실을 5년 안에, 파산하지 않고 알아내는 것**이다.
- 과거 성과의 미래 지속. McLean & Pontiff(2016)는 공표된 예측변수의 수익이
  발표 후 58% 감소했고, **표본내 성과가 높았던 것일수록 감소폭이 컸다**고 보고했다.
- 실전 비용이 가정과 같다는 것. 3단계가 존재하는 이유다.

## 위치 감각 (6부·7부 결론은 취소되지 않는다)

검증 K: **자본 1억 원에서 알파 3%면 리서치 시급은 3,000원이다.**
이 전략이 성공해도 그 산술은 그대로다.

**이것은 자산 형성의 주 엔진이 아니라, 제대로 하면 작은 엣지가 나올 수도 있는 공예다.**
위치를 알고 하면 저축·소득이라는 본 엔진을 멈추지 않은 채 병행할 수 있다.
자본이 손익분기(알파 3% 기준 약 10억)를 넘기 전까지, 같은 시간의 최고 용도는 여전히 소득 증대다.
